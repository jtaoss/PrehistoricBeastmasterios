# iOS 登录与交互回归（2026-09-20）

## 根因与修复

- 用系统 WKWebView、非持久数据区、`loadFileURL(...allowingReadAccessTo:)` 重现原始打包登录页：`login-preview.mjs` 触发资源加载错误，文档加载完成但表单 `disabled=true`、`javaCallBack` 未安装。此前只测 HTTP 网页未覆盖这个差异。
- 现在打包 `app.bundle.js` / `login-preview.bundle.js` 为普通 IIFE 脚本，目标 Safari 15。源网页仍使用模块，iOS 打包入口不用模块加载器，不开放文件跨域权限。
- 本地导航显式使用 `index.html`，不依赖 HTTP 服务器的目录首页。
- 初始化失败提供“重新载入”提示，保持认证表单关闭，不发送未绑定处理程序的原生表单请求；成功启动才解锁。
- 原生认证调用超时会释放前端请求锁；迟到回调不能接管下一次请求。注册超时提示先尝试同账号登录，不自动重复注册。
- 选关容器由 `role=img` 改为 `role=group`，使内部关卡按钮对辅助功能可见。
- Xcode 新增资源校验，源码或打包 HTML 被覆盖时阻止构建，要求先重新打包。

## 边界

隔离 UI 回归用的是模拟原生认证，不证明线上注册 API 或支付发货成功；本轮未创建真实账号、未付款、未删除玩家存档。iOS 文件导出/导入、所有机型的触摸手势和整场战斗均不算本轮完整验证范围。真机后续操作以玩家实测为准。
